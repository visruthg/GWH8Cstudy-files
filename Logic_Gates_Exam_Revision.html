  6. Do a mixed, timed run. Pick a few questions from each worksheet at random and solve them without notes. Every time, check your truth table has the right number of rows (2 to the power of the number of inputs) before you start filling it in.

The basics

A logic gate is an electronic switch that works on binary: 1 means ON or TRUE, 0 means OFF or FALSE. Computers are built from these gates, combined into logic circuits that carry out a specific job — everything from a washing machine cycle to a security lamp runs on this idea.

A truth table lists every possible combination of inputs and the output each one produces. The number of rows you need depends only on the number of inputs:

Number of inputsNumber of rows needed
121 = 2
222 = 4
323 = 8
n2n

Count your inputs first, work out 2 to that power, and that's exactly how many rows your table needs — no more, no fewer.

Notation you'll see used interchangeably: a dot or nothing at all for AND (A.B), a plus sign for OR (A+B), a bar over a letter or a prime for NOT (A′), and a circled plus for XOR (A⊕B).

Reading a circuit (circuit → expression → table)

When a circuit has more than one gate, work through it gate by gate rather than trying to see the answer in one go:

  1. List every input and give each intermediate gate's output its own letter (for example, call the first gate's output P).
  2. Write what each intermediate output equals in terms of the inputs feeding it.
  3. Build the truth table with a working-space column for each intermediate output, then a final column for the answer.
  4. Combine the intermediate expressions into one final expression once the table checks out.

Worked example — a circuit where inputs A and B feed an OR gate, whose output P feeds an AND gate together with input C:

Building a circuit from an expression

Going the other way, read the expression from the innermost brackets outward, and draw one gate per operation. Practise on these — they're taken directly from your worksheets:

  • X = (A . B) + B
  • X = (A ⊕ B) . (B + A)
  • X = (A + B) . (A . B)
  • Y = (A + B) + (A ⊕ C)
  • Y = (A . B) . ((A . B) + C)
  • Z = (X + Y) . (Y + W)
  • X = A ⊕ B . C
  • X = (A + B) ⊕ C
  • X = ((P . Q) + S) . P′
  • Y = (A′ . B′) ⊕ C′
  • X = ((A NAND B) NOR (B . C)) + C

For the longer ones, build them the same way you read a circuit — one intermediate output at a time — just in reverse: draw the innermost gate first, then feed its output into the next.

Real-world circuits

Exam questions often describe a situation and ask which gate fits. These are the classic ones from your notes and worksheets:

  • Tape recorder. The Play and Record buttons both have to be pressed for recording to start — two conditions that must both be true, so it's an AND gate.
  • Security light. A light sensor and a body-heat sensor both feed an AND gate: the lamp only switches on when it's dark and someone is there.
  • Greenhouse low-temperature alarm. The alarm should sound when the temperature sensor's input goes LOW — a single input that needs inverting is a NOT gate.
  • Night-time rain alarm. A NOT gate turns "light sensor is low" (it's dark) into a 1, which then feeds an AND gate together with the moisture sensor — the alarm needs both darkness and rain.
  • Fridge-freezer warning. The alarm should sound if the fridge door is open too long or the freezer door is open too long — either condition alone is enough, so it's an OR gate.

When you meet a new scenario, ask: does it need all the conditions true (AND), any condition true (OR), or is it just flipping one condition (NOT)? That question gets you to the right gate almost every time.

Exam-day checklist

  • Bring a pencil and ruler — circuits drawn freehand lose marks even when the logic is right.
  • Before filling in any truth table, count the inputs and write 2n in the margin so you know exactly how many rows to expect.
  • Label every intermediate gate output on a multi-gate circuit before you touch the truth table.
  • Write out NAND and NOR carefully — they're the two gates most often mixed up under time pressure.
  • For application questions, say why a gate fits the scenario, not just its name — "both conditions must be true, so AND" is a stronger answer than "AND".
